# Conditional testing evidence

English | [中文](testing-conditional.zh.md)

This reference describes harness, UI, migration, platform and performance evidence only when those objects exist. It does not establish installed test infrastructure or a passing result. The [testing policy](testing.md) owns available checks and execution rules; [conditional domain rules](defensive-patterns/conditional-domains.md) own applicable implementation contracts.

## Conditional evidence

Choose a harness by the subject and the downstream implementations that must stay real; declare replaced boundaries and limits. A whole-client fixture may combine explicit doubles: there is no universal one-double count. Durability, restoration, notification and claim-policy tests use production objects; a process-local structural stub is suitable only when its omitted behavior is not the subject. Dependencies that must not be called use fail-fast stubs. Missing services, unstubbed endpoints and exhausted scripts fail loudly, and unmatched calls fail again at teardown even when the product caught the mock error. Stateful handlers, queues and promises are test-local. A generated contract temporarily resolving to `any` is not strict-type evidence; generate and check the real declarations before delivery.

State the evidence each harness cannot provide. An allow-all UI fixture does not prove authorization denial; an in-process proxy or by-reference mock does not prove JSON encoding, generated codecs, wire names, scoped identity or gateway lifecycle. Test denial with the permissive hook overridden or real authorization. A drained stream proves pulling, not processing unless processing occurs in that read loop. A replay bound by first-call order does not prove concurrent sibling determinism. A shared arrival-order fault cursor does not assign a fixed fault per concurrent session; isolate instances when needed. Record pressure-test seeds; synthetic weights are not production incident frequencies. Direct-child termination does not prove the whole process tree is gone.

For UI changes, exercise real browser user paths, not just render helpers: first-frame values, stable nodes/focus/selection/drafts, list insertion/removal identity, two concurrent scopes, keyboard access, reduced motion, route subpaths and real cleanup as applicable. Real runtime registration tests dispose its owner and observe removal; hand-built injection does not prove the shipped loader/composition. Test a platform's real boundary on that platform and report skips and missing capabilities explicitly. A green suite running zero tests or scanning zero required source objects is not acceptance.

Historical input, migrated-result oracle and current native-writer oracle are independent artifacts. Compare migrated and native target output before format normalization; mask only declared volatile fields, never structural differences by converting back to the old format or stripping them. Keep user corpora read-only and derive sanitized fixtures before use. An authorization-denial test's working directory must actually be outside ambient automatic grants; a temporary directory already granted by the harness cannot prove denial. Include a legitimate explicit-grant positive case.

Resource tests use private exclusive paths, dynamically allocated ports and caller-owned cleanup. Preserve a caller-provided working directory; do not delete it as harness-owned. Wait for observable work and child exit, restore environment even after failure, and distinguish process-tree limits. A designed refusal checks its documented exit status rather than merely any failure. Performance claims use real user paths, isolate preparation from measurement, identify machine/platform, retain raw samples and stated budgets, and verify scaling against representative workloads; synthetic output or one timing cannot establish a general speed or memory claim. Real API credentials, recordings, remote mutations and host changes require their own authorization; missing permission is a reported evidence boundary, not a fake fallback.
