# 翻译规则

[English](translation-rules.md) | 中文

这些规则适用于现有中英文治理文档配对的更新。根据[配对规则](README.zh.md)，两种语言同权。任一侧都可以先撰写；作者在同一变更中更新对侧。必须（MUST）与禁止（MUST NOT）属于审查要求，应当（SHOULD）在偏离时需要理由，可以（MAY）由作者裁量。本仓库未安装自动翻译门禁。

## 忠实性

- 对侧必须保留全部行为、前置条件、警告、版本声明与示例。如果配对内容冲突，先依据实际事实修正错误的一侧，再更新另一侧；没有哪种语言默认获胜。
- 对侧应当是其语言自然的技术文字，而不是逐词对照。重组句子时保留语义与语域。
- 当直译可能误导时，翻译习语的含义，而不是其字面措辞。

## 行文

- 使用简洁、专业的技术文字。参考最接近的[语体样例](style-samples.zh.md)校准；术语、忠实性与结构要求优先。来源样例不是本插件的运行时约定。
- 保留每个执行者、条件、义务、例外与后果。流畅不能成为省略语义成分的理由。
- 当目标语言可能掩盖执行者时，明确说明由谁执行。
- 优先采用通行工程术语与自然解释，避免生硬直译或照搬名词链。
- 一段一件事，一个段落一个物理行。目标语言语法需要时，可以拆分段落。
- 英文行文使用通行的英文类别名。中文行文按术语表要求在首现时括注英文。字面路径保持不变。

## 结构保持

直接审查两个文件；本仓库没有结构签名检查器。配对必须保留：

- 标题层级与顺序，并翻译标题文字；
- 列表形态、顺序与编号；
- 表格列与行序，并翻译文字单元格；
- 逐字节一致的围栏代码块，包括注释与信息字符串；
- 行内命令、flag、配置键、路径、事件与 API 名，以及版本号的原文；
- 等价的链接目标及完全相同的 query 与 fragment 后缀。目标有对侧文件时使用同侧语言，单语目标保留路径。外部 URL 与图片保持不变。语言切换行有意跨语言。

相对链接与片段锚点必须可解析。文件末尾恰好保留一个换行。文档片段不会自动编译或做类型检查；可运行示例变动时，通过实际归属入口验证。

## 术语

- 翻译前阅读[术语表](terminology.md)。遵守每行的译法、首现括注与禁用替代词。英文目标使用 English 列，不加中文括注。
- 未收录的中文技术术语可以使用主流中文 OSS 或厂商资料中的通行译法，并在审查时引用来源。否则保留英文，将建议译法报告为待定。
- 英文目标使用通行英文技术术语。如果来源术语没有明确对应词，保留原词、加简短说明，并报告为待定。将已确定的术语加入术语表，不自行创造局部替代词。

## 排版

中文行文遵循 [MDN 翻译指南](https://github.com/mdn/translated-content/blob/main/docs/zh-cn/translation-guide.md)、[Kubernetes 本地化指南](https://kubernetes.io/zh-cn/docs/contribute/localization_zh/)、[Vue.js 翻译须知](https://github.com/vuejs-translations/docs-zh-cn/wiki/%E7%BF%BB%E8%AF%91%E9%A1%BB%E7%9F%A5)与[中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines)的中西文混排约定：

- 中文与拉丁词或数字之间留一个半角空格；全角标点旁不加空格。
- 中文行文使用全角中文标点。代码、英文原文引用与数字内部保留半角标点。
- 优先使用句号、逗号、冒号或括号，除非破折号能更自然地表达含义。
- 中文并列项之间使用顿号。
- 使用半角数字与拉丁字母。
- 保留专有名词的规范大小写与代码的精确拼写。
- 称呼读者为「你」，不用「您」。
- 在等价文字范围保留强调；不要用装饰性引号替代强调。

## 质量标准

- 双语工程师只读任一文件时，必须获得相同的事实、告诫与含义，没有额外声明。
- 逐个语义成分比较配对，再检查结构、术语、链接、代码与排版。分别报告人工审查与实际命令；不虚构 hash 确认、自动检查或人工批准。
