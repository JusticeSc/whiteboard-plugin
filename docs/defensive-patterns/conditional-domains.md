# Conditional domain rules

English | [中文](conditional-domains.zh.md)

These review rules apply when the named object exists. They preserve ownership and evidence requirements without requiring a browser, remote protocol, plugin host, model runtime or Session store. [General rules](general.md) still apply; [testing](../testing.md) owns the active evidence boundaries. [Project context](../PROJECT-CONTEXT.md) owns the concrete product contract.

## UI identity and state

Keep component type identity stable for controls holding a draft, focus, selection or an internal instance. An unrelated update must not replace their DOM node or remount the component. Prepare data and initial values in the first flow, not a later effect. List keys identify the entity or instance and are unique; a mutable-list index is not identity, and collisions require fixing the ID source. A deliberately required remount is allowed when the instance-lifecycle reviewer accepts the reason and state-migration plan; test the intended migration.

Business data, shared interaction state and settings each have their own owner. Pass the required data, selector and action rather than an entire service or store. Derive multi-instance context from the current scope, not a new global `current`, `active` or `selection`. Local fold, hover and draft state stays local; a truly global singleton is explicitly injected. Reuse an existing resource fetch/cache/invalidation owner rather than adding feature-local competing subscriptions or caches. A new subscription hook explains its subscription impact in review; protocol hooks belong to the protocol owner, while value wrappers may reshape values without hiding ownership.

Do not use an effect to send render-derived data through a setter received from props, including clearing it in cleanup. First render the data at its owner; when needed deliver during render; give truly shared data a declared shared owner. Real external subscriptions, event callbacks and user gestures are outside this pattern. Any other exception requires the owning domain expert's confirmation; replacing `useEffect` with `useLayoutEffect` is not a fix.

A feature absorbs its own requirements first. Keep a new control feature-local until a second real consumer justifies promotion; promote ownership as its own reviewed change. Adapt shared layout with a feature wrapper, style or layer instead of teaching the shared layer one feature's ordering or semantics. A genuinely general shared change is allowed with its domain expert's confirmation and regression coverage for every consumer. Shared grouping, list, rendering and Markdown pipelines take explicit semantic data or a registered renderer, not single-business fields or traversal branches; shared sorting, virtualization, accessibility, generic Markdown and attachments are legitimate shared responsibilities.

Framework-specific restrictions activate only with their host. In a Slot-based host, declare injection and child slots rather than passing host contexts, direct observables or markup-valued props through the feature boundary; touched legacy markup-valued fields convert in the same change unless a domain expert accepts deferral. Dynamic features do not runtime-import or re-export another feature's implementation. Use official extension entries and preserve their fallback and complete-label contracts. These are not a ban on ordinary React Context or `useSyncExternalStore`, nor a demand to adopt Slot or Cordis.

## Client styling and assets

Client build changes extend the existing shared build owner, not an independent per-package build branch. Use CSS Modules and `clsx`, not a newly introduced component library or Tailwind. Reuse existing controls. Feature styles consume semantic theme tokens rather than copied palette values, literal colors, a second global theme or local light/dark selectors. Global sheets, theme, motion and elevation each have one owner; concrete token names and visual values belong to that owner's actual protocol.

Put static values and variants in CSS classes; inline style is for runtime measurements or component-local custom properties, such as a measured gutter or progress. Keep images, GIFs and SVGs in CSS resources rather than JSX; do not embed base64 or large text in TSX. Explain a new build branch or inline form in review before landing under the owning package's rules. Pair font and line-height; preserve required widths, scrolling, visible focus and reduced-motion behavior. Source-specific controls, platform visual backing and theme values apply only when that control/theme protocol is actually adopted.

Browser requests and resource URLs resolve relative to the current document and work below a reverse-proxy subpath. An internal absolute route key does not permit emitting root-absolute request URLs. Transport, proxy, certificate and timeout policy have one owner; an independent transport states why and remains proxy-aware.

## Remote contracts and recovery

Give a remote business capability its own cohesive service or object; one caller is not a reason to merge unrelated capabilities. Keep authentication and resource authorization at the operation that acts, including alternate and direct calls. If a generated-client protocol exists, mark exposure on the concrete operation, derive client types from the same definition, and retain its single wire codec and output-validation path. Do not hand-copy client contracts or add a second output decoder. Existing exposed names retain their meaning; new semantics get a new entry. A rename or new decoding path states its benefit and caller impact and needs domain-owner confirmation, not author self-approval. Ordinary in-process methods are outside these exposure rules; a genuinely single-business service need not split. Streams, pagination and projections keep their own protocol instead of becoming ordinary RPC descriptors merely because they share a carrier. No particular decorator, Peer or gateway framework is required.

The host owns authoritative business state; a client mirror declares stable identity and how delayed replies merge with or yield to a newer baseline. Physical reconnection is not logical recovery. Choose baseline, cursor or query recovery by the data's semantics; ordinary notifications are not replayable history. Keep business/protocol errors separate from carrier failures rather than erasing them with generic retries. No stream means no obligation to invent resynchronization, and different domains need not share a universal recovery runtime.

## Derived state, persistence and resources

Publish notifications, derived state and externally visible results only after the authoritative operation commits; a failure leaves the log, views and feeds consistent. Use one lifecycle controller or transaction for one asynchronous operation unless a second readiness, reservation or settlement point genuinely has a separate owner. Follow the [project persistence and compatibility contract](../PROJECT-CONTEXT.md); never rewrite released inputs or user data merely to make a migration pass.

For an authoritative log-derived projection or equivalent cache, use its one published read/calculation path and default to complete calculation; narrowing it needs the owning domain expert's confirmation. A partial projection serves UI availability, not external decisions. At its client boundary a miss or stale state is explicit, not a silent whole-log cold read, even for a small history. Necessary host cold reads and a separately named cold-read operation when no projection exists remain legitimate. This is not a ban on recomputing arbitrary ordinary caches.

A reference-counted shared resource uses explicit acquire/use/release; idle reclamation requires zero references and no inflight work, not an enumeration of business states. Review may verify a release trigger manually. For a high-frequency stream, calculate incrementally and publish in batches with stated complexity; do not recompute the entire history and publish immediately per chunk. Structural or terminal changes may publish immediately; a cadence name alone is not evidence of a defect. Do not require reference counting for ordinary CRUD without such a shared resource.

## Display metadata without activation

When reading package display metadata, do not activate or execute the package, including disabled or untrusted plugins. Title and description fall back independently. Missing fields may fall back; malformed JSON or invalid fields produce a per-package diagnostic. Images are in publication `files`, resolve inside the real package boundary, and reject absolute paths, URLs, escaping paths or symlinks. Images must be self-contained, including their dependencies; render SVG as an image, not inline HTML. An explicitly invalid icon preserves valid text and produces a diagnostic without trying a competing icon export; a missing or undecodable image may use the default.

Package-root and plugin-subpath addresses keep their actual protocol: a subpath is not a package and must not read a fabricated nested `package.json`. Allowed formats, maximum bytes and locale chains are explicit metadata-contract parameters, not universal upload limits. Generated output resources do not themselves establish an installed-package metadata protocol.
