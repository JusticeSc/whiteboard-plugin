# Agent Notes

[English](README.md) | 中文

**Agent Note** 记录代码、测试与现有产品文档无法承载的长期决策依据、被否决的方案、后果与必需验证。这些规则是本插件中需人工审查的指导。仓库未安装记录格式、翻译或归档校验器；实际检查以 manifest 与 CI 为准。已有产品决策仍由 [DECISIONS.md](../../docs/DECISIONS.md) 与 [ADR](../../docs/adr/) 拥有，不在此重复。

## 布局与命名

使用 `{lifecycle}/{class}/yyyy-mm-dd-topic-title.md`，新双语记录附 `.zh.md` 对侧文件。使用记录可支持的首次提出日期，不虚构日期。生命周期包括：

- `proposed/`：尚未实施或只实施了一部分的重大未来工作。
- `implemented/`：已交付的决策，按[对应指令](implemented/AGENTS.md)保持事实准确。
- `rejected/`：被否决的提案，仅在其依据能防止合理且影响重大的错误时保留。

活跃生命周期目录就是清单；不要另建重复的集中索引。通过相对 Markdown 链接交叉引用实际归属记录，不用无法解释的编号或纯标题。

## 分类

按以下人工审查约定选择一个路径类别；本仓库没有分类门禁：

| 类别 | 主题 |
|---|---|
| `feature` | 面向用户或模型的新能力。 |
| `bug-fix` | 缺陷或事故复盘发现的缺口。 |
| `simplification` | 不增加能力地移除代码、行为或对外范围。 |
| `architecture` | 交付源码的结构、归属或运行时词汇。 |
| `process` | 源码周边工具与工作流，不是运行时行为。 |
| `testing` | 测试基础设施或策略。 |

机械重构不因代码移动就需要单独的类别或记录。仅在别处尚无归属时，记录具有长期价值的命名、兼容或归属决策。

## 何时需要写一份

仅为现有归属文档缺失的长期依据创建或更新记录。添加前，搜索相同机制或决策的活跃记录，并应用[取代关系审查](../skills/dsh-archive-agent-notes/SKILL.md)。更新当前归属记录，不重复创建。机械编辑与轻微局部 UI 调整不需要记录。

部分被取代的记录保持活跃并互相链接。不同决策需要新的归属记录，不把旧决策改写成反面。只有新归属完整保留每项独有依据、替代方案、后果、必需验证与具名覆盖缺口时，才可通过完整合并删除活跃旧记录；修复所有入站链接，并一并移除活跃对侧元数据。

将功能添加记录合并进移除记录，要求该功能完全不存在于生产代码、配置、schema、持久化和协议格式、迁移、兼容、当前可用性声明及受支持行为测试中。保留动机、移除依据、被否决方案、放弃的能力、重新引入条件与真实的缺失验证。只移除一种传输、默认值或展示属于部分取代。

## 文件格式

人工核对状态与生命周期目录一致。以以下字面头部开篇，后跟一个空行：

```markdown
# Agent Note: <title>

Status: <status>
```

状态使用 `proposed`、`implemented` 或 `rejected — <one-line reason>`。文件名拥有首次提出日期；状态行不带日期或括号中的修订说明。

正文以 `## Problem` 开始，独立于解决方案说明动机。提案随后包含 `## Proposal`、`## Alternatives considered`、`## Acceptance criteria` 与 `## Risks`。已实施记录包含 `## Decision`、`## Alternatives considered` 与 `## Consequences`，按已交付事实撰写；实际测试、延后缺口或相关归属放入明确命名的章节，不保留实施计划。否决记录保留提案正文，在状态行说明原因。

记录真实的替代方案及其落选原因。绝不虚构讨论、批准或证据。如果无法恢复历史备选方案，明确说明限制。保留拥有有用细节的自定义技术章节。按[人工配对规则](../../docs/i18n/README.zh.md)在中文对侧保留字面头部标记与对应结构；新的活跃配对不需要 hash 伴随记录。

## 归档与删除

只有活跃已实施记录仅描述轻微 UI 展示或纯机械变更时才删除；同时移除对侧与伴随元数据，并修复入站链接。bug 修复、性能变更、新能力或实质归属决策，不因实现规模小就属于轻微变更。只要其中的替代方案、否定性保证、持久化或协议语义、归属边界、安全规则或重新引入条件仍能指导未来工作，就将实质记录保持活跃。

具有历史价值但未来指导价值较低的已实施记录是归档候选。提案绝不归档：保留有效提案或否决过时提案。只有落选想法仍构成合理陷阱时才保留否决记录；否则移除完整活跃配对与元数据，并修复入站链接。不按年龄、字数或配额分类。

移动候选前遵循[归档指令](archived/AGENTS.md)。本 checkout 没有归档封存校验器，因此候选不等于已封存归档，也不能声称自动 hash 保护。明确评审归档流程可用前，候选保持活跃。既有已封存英文、中文与伴随记录三文件组永久冻结：禁止编辑、翻译、重排格式、修复内部链接、移动或删除，也不得将其作为当前权威依据。
